# 科研系统页面职责与真实使用流程 v1

> 内部维护文档。用于科研系统后续功能去重、职责检查和真实使用流程完善，不在前端页面展示。

## 一、总体原则

科研系统后续不再以“页面越多、图表越多”为目标，而以“职责清晰、流程闭环、数据真实、入口唯一”为目标。

统一采用以下四层结构：

1. **总览/分析层**：发现问题、观察趋势，不承担数据维护。
2. **查询层**：跨模块定位项目、成果、教师，不承担编辑。
3. **详情层**：查看单个项目、成果、教师的完整信息与关联信息。
4. **管理层**：新增、编辑、维护、导出业务数据。

统一跳转原则：

- 聚合数据 → 综合查询（带筛选条件）
- 单个项目 → 项目综合详情
- 单个成果 → 成果综合详情
- 单个教师 → 教师科研画像
- 详情页如需修改 → 对应业务管理页
- 分析页不直接承担新增、编辑
- 管理页不重复承担院级趋势分析

## 三、真实使用流程

### 流程 A：院级管理者查看科研运行情况

科研总览
→ 发现某项指标异常 / 待办风险
→ 智能分析或综合查询
→ 项目 / 成果 / 教师详情
→ 如需处理
→ 项目 / 成果 / 经费管理页

### 流程 B：查找某个科研对象

综合查询
→ 输入关键词/年份/系别/学科/教师等条件
→ 项目 / 成果 / 教师结果
→ 单个详情页

### 流程 C：学科负责人查看本系表现

学科分析
→ 查看本系趋势和结构
→ 点击真实聚合图表进入带条件的综合查询
→ 查看具体项目 / 成果 / 教师
→ 单个详情

### 流程 D：教师查看个人科研情况

教师科研画像
→ 查看个人项目 / 成果 / 经费 / 风险
→ 点击具体项目或成果
→ 对应详情页

### 流程 E：业务人员维护数据

科研项目 / 科研成果 / 科研经费
→ 筛选业务数据
→ 新增 / 编辑 / 导出
→ 如需查看关联背景
→ 进入对应综合详情页

## 四、下一阶段去重重点

### 1. 科研总览 vs 管理员智能分析

科研总览只保留：
- 少量核心 KPI
- 关键趋势摘要
- 待办与风险摘要
- 快速查询入口

管理员智能分析承担：
- 风险深度分析
- 教师绩效分析
- 资源配置分析
- 复杂图表和诊断结果

### 2. 科研总览 vs 学科分析

科研总览不再重复各系详细指标；
学科分析负责分系结构、趋势和代表对象。

### 3. 科研项目/成果管理页 vs 详情页

管理页负责“列表 + 操作”；
详情页负责“单对象完整阅读”。
不在详情页重复放编辑表单，不在管理页堆叠完整关联分析。

### 4. 综合查询 vs 各业务筛选

综合查询负责跨模块、跨对象定位；
项目/成果/经费页筛选只服务本业务管理，不升级成跨模块搜索。

## 五、前端展示规范

以下内容属于内部开发/数据治理信息，不在正式用户界面展示：

- “点击图表下钻”等开发提示
- “演示数据 / 模拟数据 / 仅作演示”等研发说明
- “当前数据模型未建立某外键”等实现说明
- “图表不会补造缺失指标”等开发说明
- 数据来源字段、测试标记、内部版本号说明

这些信息仅保留在：
- 后端数据字段
- 测试与审计脚本
- 本内部维护文档
- Git 提交说明

正式页面只展示业务信息和必要操作提示。
